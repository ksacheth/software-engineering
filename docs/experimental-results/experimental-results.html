Website Vulnerability Scanner: Experimental Results

Team WVS: Deepthi (241IT021), Jasmine (241IT051) and Sacheth Koushal (241IT058). Software Engineering (IT303), October 12, 2026.

1. Aim

Measure how well WVS finds real weaknesses on a website it is allowed to scan, how long a scan takes, and whether the code behaves as specified.

2. Setup

  • Target: vuln-lab, a deliberately weak test website (source in tools/vuln-lab), deployed at http://vuln-lab.sacheth.tech. Each weakness is planted for one or more detectors, as listed in tools/vuln-lab/README.md.
  • Ownership: verified with the well-known file method before scanning, as WVS requires.
  • Scan: STANDARD profile (10 requests per second, concurrency 5, depth 5, at most 200 pages and 2,000 requests). Only /logout was excluded from scope.
  • Scan ID: cmv4r3v5f0009x8p455ba5tyj, run on October 12, 2026.
  • Stack: WVS running locally (React web app, Express API, BullMQ scan worker, PostgreSQL 16, Redis 7).

7. Conclusion

WVS found 33 of the 34 detector checks planted in the test website, a 97% detection rate, in under a minute and within its request-rate limit. Its output is triaged in the app and exported as executive and technical reports. All 1,233 automated tests pass. The missed path traversal case (A-11) is the main item for future work.
